# Saved Relations To Native Graph

## Scope

Connect saved topic-knowledge relations to the native App and both endpoint references.
Reuse organization snapshots, versioned paper keys, the existing read command, ledger and
report/evidence navigation. Preserve the accumulated worktree changes and previous Apps.
No model, service, credential, delivery, commit, push, release or automatic organization.
The independent HTML prototype and its invented interaction data are not production inputs.

## Responsibilities

- Python projection: include saved relations with a stable ID derived from the unordered
  endpoint pair and relation kind. Preserve reason, basis and exact reference IDs. Do not
  infer relationships, persist coordinates or rewrite snapshots/reports.
- Swift Core: typed undirected relations, strict field validation, count/identity checks,
  allowed kind/basis and references covering exactly both supplied endpoint paper versions.
  Old zero-relation projections remain readable; missing relations with a nonzero count fail.
- App: topic-scoped graph selection, camera, relation filters, node focus and evidence details.
  Display one node per supplied paper version. Classification membership is not a semantic edge.
  Reuse existing source quotations/links and report navigation rather than interpreting prose.

## Exact Evidence Navigation Repair

The subsequent approved offline investigation reproduced a real App navigation defect, not just
a short test timeout. A saved knowledge reference identifies a particular claim in its original
report. The graph-to-reader route retained the report, paper and report hash, but discarded the
claim index. The reader therefore finished its pending navigation at the evidence section header;
a late quotation could exist in the accessibility tree while remaining below the visible window.
Waiting longer did not supply the missing target.

The repair is App-only: carry the validated reference's paper-local claim index in the existing
ephemeral navigation entry, reject an out-of-range index, and scroll to that claim's row after the
existing figure-layout readiness check. Continue using the ledger's flattened paper index and the
reference's report hash. Clear the pending claim with the existing navigation lifecycle. Generic
ledger evidence actions still open the section header; chapter menus and evidence disclosure
behavior are unchanged. There is no new timer, wire field, persistent setting or scrolling retry.
