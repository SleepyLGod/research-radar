# macOS App 入门

[English](macos-app.md) · [项目首页](../README.zh-CN.md)

ResearchRadar App 把搜索论文、阅读全文、核验证据和阅读报告放进 macOS 菜单栏。
第一次使用先做一件事：**生成一份本地报告。微信、邮件和定时任务稍后再配。**

当前是开发中的本地 beta，只支持 **macOS 26、Apple Silicon（arm64）**。
已生成本地测试 DMG，并通过只读打包检查，尚未验收安装或启动。
最新测试包已清理 Python 构建元数据里的本机路径，但仍沿用开发数据目录，详见[路线图](todo.md)。
它不会自动替换现有开发 App 或已安装的 App。
目前没有公证或获准公开分发的安装包。
完整资源、键盘、VoiceOver、多屏等最终验收仍有未完成项，见[路线图](todo.md)。

## 1. 打开 App

如果维护者已经给了你构建好的 `ResearchRadar.app`，双击即可。
App 自带 Python engine，运行它不需要另装 Python、`uv` 或 Homebrew。
选择 Codex 核验时，仍需要可用的 Codex 可执行程序和已有登录；它不包含在 App 里。

如果你从源码开发，请先切到包含 App 的开发分支，在仓库根目录执行：

```bash
./script/stage_macos_app.sh
open dist/ResearchRadar.app
```

这是开发构建流程，需要 `uv`、Python 3.12+、Swift 6.3+ 和 macOS 26 SDK。
首次会下载依赖并产生构建文件，不是普通用户每次启动 App 的步骤。
脚本会运行 Swift 测试、打包和本地检查；这不等于完成全部 Python、离线工作流或人工验收。
若系统拦截开发版，请先核对来源并让维护者检查签名，不要关闭系统安全保护。

打开后看屏幕顶部的菜单栏图标，不要只在 Dock 里找窗口：

- 左键点击：打开或收起图标下方的面板。
- 右键点击：打开原生菜单，可运行当前主题、暂停计划或退出。
- 面板右上角：切换紧凑和完整模式；完整模式有主题、报告、设置和诊断入口。
- 点击面板外部或按 Escape：收起面板，不取消后台研究；有确认弹窗时，先处理弹窗。

App 使用自己的设置，不自动读取 CLI 的 `config.yaml`。
已经用过 CLI，也请检查 App 中实际保存的主题、服务、收件地址和计划。

## 2. 完成首次配置

首次引导有四步，可以返回修改。收起面板不等于退出 App；已保存的配置重启后仍在。
尚未保存的 API key 不会作为表单草稿持久化。

### 第一步：外观与语言

界面语言可选跟随系统、简体中文或 English；外观可选跟随系统、浅色或深色。
之后也能在「设置 → 通用」修改。

**界面语言和报告语言是两回事。** 界面切成英文，不会把已有中文主题的报告改成英文。
新主题默认采用当前界面对应的报告语言，保存前仍可单独选择中文或 English。

### 第二步：模型与搜索服务

| 服务 | 做什么 | 你需要准备什么 |
|---|---|---|
| DeepSeek | 生成主题草稿、整理来源、精读和翻译等 | DeepSeek API key |
| Tavily | 搜索相关网页，补充论文发现 | Tavily API key |
| Codex（默认核验） | 对照证据核验准备公开的结论 | 可执行程序、已有登录及可用模型权限 |

API key 是服务商发给程序使用的凭据，**不是你的账号登录密码**。
DeepSeek、Tavily 和 Codex 使用各自的账户及额度；生成主题、检查连接和研究可能收费，
以服务商账户显示为准。不要把 key 发到聊天、截图或提交到 Git。

按下面顺序操作：

1. 在 App 的 DeepSeek 区域点击申请入口，取得 key 后粘贴，并单独保存。
2. 在 Tavily 区域同样保存搜索 key。默认 App 路线需要这两个服务。
3. 确认各自显示「已保存到钥匙串」。保存后输入框清空是正常行为，不必每次再填。
4. 若检测到了 Codex，点击「使用检测到的 Codex 安装」。已有有效路径不会要求重复选择。
5. 未检测到时，在高级设置中选择 **Codex 可执行文件**，不是选论文、项目目录或 API key。
   App 不会替你安装或登录 Codex；先完成其安装、登录，再回来确认路径。

默认 DeepSeek 模型是 `deepseek-flash`，显式开启 thinking，强度为 `high`。
默认 verifier 是 Codex `gpt-5.6-luna` / `xhigh`，App 可选择「高 / high」或「极高 / xhigh」。
这不修改全局 Codex 配置，也不保证你的 Codex 账户能使用某个模型。

Codex 不可用时，可以**明确选择 DeepSeek 核验并确认提示**。
App 不会自动切换；切换后阅读和核验都使用 DeepSeek，不再是两个不同服务交叉检查。
任意自定义 provider 或高级模型路由继续使用 [CLI 配置](providers.md)，不在本版 App 的编辑范围内。

这三个状态要分开看：

- **已保存**：本机有凭据，不等于当前程序已获准读取。
- **已找到程序 / 配置完整**：本地条件满足，不等于服务可连接。
- **测试连接通过**：仅表示标为通过的检查项目当时成功，不保证后续研究质量或投递成功。

### 第三步：创建并审核研究主题

输入自然语言描述，例如：

> 关注 LLM agent 的长期记忆，重点看记忆更新、遗忘、冲突处理和评测，不关注传统硬件存储。

选择报告语言，点击「生成主题草稿」。**这一步会调用模型**，不是纯本地表单操作。
随后审核主题名称、研究重点和搜索范围。搜索词、概念组和排除词在高级区域，可以展开修改。
处理质量提示后保存主题，不要直接把模型生成的搜索范围当成已经审核过的需求。

默认精读上限为 2 篇，最终核对页会展示数量；本版界面暂不提供精读数量编辑控件，也不保证凑够两篇。
以后在「主题」新增、选择、编辑或暂停主题。已有主题不会被界面语言切换改写。

### 第四步：检查并开始

1. 核对主题、报告语言、精读数量以及实际模型路线。
2. 点击「测试连接」。它会发送模型请求和一次小型搜索，可能消耗额度；不会测试微信或邮件。
3. 如有失败，按对应服务的提示处理。更换凭据、模型或强度后，重新检查，不沿用旧结果。
4. 确认微信、邮件和每日计划仍未启用，再点击「开始首次研究」。

也可以选择「完成设置，暂不运行」，以后从首页点击「立即运行」。
研究需要联网，等待时间取决于搜索、全文获取、模型和论文数量，不是一个固定的倒计时。
运行期间部分设置不可修改；先等待或取消任务，不要把变灰的保存按钮当成配置丢失。

## 3. 阅读第一份报告

首页显示本次尝试和上次有效报告；在「报告」选择报告并打开正文。
来源数、精读数和已核验结论数属于对应报告，不代表本次失败已经产出了这些内容。

| 本次结果 | 应该怎么理解 |
|---|---|
| 有可公开精读报告 | 可以阅读，符合条件时可以投递 |
| 没有合格的新候选 | 本轮没有可精读的新候选，不等于 Codex 拒绝了所有结论 |
| 研究未完成或证据不足 | 去诊断看是搜索、全文、阅读还是核验阶段的问题 |

精读上限不是产出承诺。证据不够时，App 不会为凑两篇而放宽标准，空结果也不会自动投递。
同一天已有有效报告时，「立即运行」会选中已有报告；要重新研究，请使用「重新运行」并确认。
这是新尝试，不是断点续跑，可能再次产生费用。

收起面板后研究会继续。要停止当前任务，使用任务的取消操作；要退出 App，使用菜单栏右键菜单。
退出会停止 App 调度并取消当前工作，不会留一个隐藏 scheduler 替你继续运行。

## 4. 可选：微信草稿与私人邮件

设置中有两个开关：「研究完成后创建微信草稿」「研究完成后发送邮件」。
**启用并保存后，后续手动研究会自动投递合格报告，不会每次再弹发送确认。**
微信和邮件各自进入独立任务；定时任务使用保存计划时记录的渠道。

只想先读后发：研究时保持这两个开关关闭；生成报告后再配置、启用所需渠道，
从该报告页点击投递按钮并确认。保存渠道设置本身不会补发旧报告。
后续不想自动投递时，关闭对应开关；如已设置每日计划，也重新保存计划，核对其渠道。

### 创建微信草稿

1. 在「设置 → 微信公众号草稿」填写公众号 `AppID`、`AppSecret` 和作者，点击「保存微信设置」。
   凭据也可以先保存，暂不开启研究完成后的投递。
2. 设置封面：点击「选择封面…」，预览 PNG/JPEG；当前限制为 2 MiB、4000 万像素。
   **选图不会上传**；点击「上传封面」并确认后才联网上传到该公众号永久素材库。
   已有封面素材 ID 也可在对应高级区域填写。
3. 核对开关和已保存封面，在报告页点击「创建微信草稿」，确认后操作。
4. 成功后去微信官方后台草稿箱检查排版和图片，再自行决定是否发布。

ResearchRadar **只创建草稿，不发布、不群发**。封面上传不等于创建草稿。
公众号需要有相应接口权限；若微信返回 IP 白名单错误，按返回信息核对当前出站公网 IP，
不要把服务连接失败直接当成账号身份错误。
上传成功但本地保存失败时，使用「保存已上传封面」，不必重新上传。
结果不明时先检查微信素材库或草稿箱；重复确认可能产生重复素材或草稿。

### 发送私人邮件

在「设置 → 私人邮件」填写 SMTP 主机、端口、用户名、应用专用密码、发件地址和一个收件地址，
然后点击「保存邮件设置」。**当前 App 表单保存的是隐式 TLS 配置，不提供 STARTTLS 选择。**
CLI 的 SMTP 选项更广，不要把 CLI 的 STARTTLS/587 示例直接套到这个表单。

Gmail 自发自收的填写示例：

| 字段 | 填什么 |
|---|---|
| SMTP 主机 | `smtp.gmail.com` |
| 端口 | `465` |
| 用户名、发件地址 | 你的完整 Gmail 地址 |
| 应用专用密码 | Gmail 的 16 位 App Password，不是普通登录密码 |
| 收件地址 | 首次建议填你自己，先确认效果 |

Gmail 应用专用密码需要按 Google 的账户流程设置两步验证；若账户不提供此选项，
先向服务商确认可用的 SMTP 授权方式，不要反复输入普通密码。
其他邮箱使用其提供的隐式 TLS SMTP 配置。

在报告页点击「发送邮件」，核对报告、发件人和收件人，确认后发送现有报告，不重新研究。
HTML 和纯文本正文都会提供，安全 PNG/JPEG 图片通过 CID 内嵌，不依赖 Archive 在线图片。
这是一对一私人邮件，不是订阅、群发或营销邮件服务。

微信和邮件分别记录状态；一个渠道失败，不会撤销成功报告或另一个渠道的成功结果。
已发送、已创建或结果未知时，重复操作会有额外确认。**未知不等于失败**：先查收件箱或草稿箱，
确认是否已经收到，再决定是否重试；App 不会自动重发未知结果。

## 5. 可选：每天自动运行

1. 在设置里先选中主题，进入「每日定时」。
2. 选择时间，勾选「为当前主题启用」，核对所需投递开关，点击「保存定时设置」。
3. 确认「暂停全部定时任务」没有开启，主题本身也未暂停。保存计划不会解除全局暂停。
4. 如希望登录 Mac 后自动启动 App，再明确开启「登录时启动」，并在系统设置中确认登录项获准运行。
   App 里的开关表示保存的偏好，不保证系统已经批准。

App 使用本机当前日历和时区解释每日时间。它必须保持运行，收起面板没关系；
**明确退出 App 后就不再执行计划**，也不会为此安装常驻 helper 或 launchd 任务。
当前开发版仍有非公历下报告日期错误的已知问题；使用非公历系统设置时，先核对日期，不要依赖无人值守调度。
App 调度与 CLI 的 launchd scheduler 是两套入口；发现旧任务冲突时先处理旧任务，
App 不会自动删除它们。

睡眠或未运行期间错过计划，只考虑当天尚未尝试的任务，不追补往日：
例如昨天漏跑，今天 08:00 打开、计划为 09:00，就等今天 09:00，不先补昨天。
当日已失败或取消的尝试不会自动循环重跑，请手动处理后重试。
若显示异常停止，去设置点击「重新检查并恢复」；恢复校验失败时仍会停止，不绕过损坏状态。

## 6. 钥匙串为什么还会弹窗

输入 API key 是保存凭据；macOS 的「允许 / 始终允许」是允许某个程序读取某个项目。
弹窗里要求的通常是本机钥匙串密码，不是让你重新填 DeepSeek key。
不同凭据或不同请求程序可以分别弹窗，因此一次运行出现多次授权，不一定是在重复保存同一个 key。
也不能只凭弹窗次数断定一切正常；遇到异常，记下请求程序和项目名称，不要记录密码。

保存后无需每次重填 key；输入框清空、显示已保存，也不表示程序已经获准读取。
只在确认请求程序和凭据属于可信的 ResearchRadar 时考虑「始终允许」。拒绝后应按错误提示处理，
不要为了消除弹窗而放开所有应用访问、改成明文文件或修改钥匙串 ACL。

**本地自签名证书没有彻底解决跨版本授权。** 开发版重新构建后仍可能再次请求授权，
即使之前点过「始终允许」。不能承诺配置一次后所有更新永不弹窗。
详细边界见[钥匙串授权说明](usage.md#macos-app-keychain-authorization)。

## 7. 出问题时先看哪里

在「诊断」点击「复制脱敏诊断」，附上你做了什么、界面提示及是否已收到投递结果。
复制操作使用已有状态，不会运行连接检查、读取密钥或重新发送。
分享前仍请检查截图，避免暴露邮箱、API key、私有路径和未公开报告。

- **提示配置缺失**：检查保存状态、Codex 路径和实际 verifier；找到程序不等于已经登录。
- **选择 Codex**：选择可执行文件本身，不要填写带参数的命令。路径可以包含空格或中文，
  不需要自己加引号；CLI 配置仍支持[带参数的命令](providers.md#cli-agent-providers)。
- **连接检查失败**：按对应服务检查凭据、权限、额度和网络，不必重新填所有服务的 key。
- **显示研究停止**：看本次时间、阶段和原因，不把上次报告的统计当成本次结果。
- **精读或通过数为零**：先区分未选中候选、全文不足、阅读失败和实际核验未通过，不先归因于 Codex。
- **发送结果未知**：先检查邮件或微信后台，不直接连点重试。
- **设置变灰**：活动或排队任务期间会限制影响行为的配置修改；等任务结束或先取消。
- **持久状态损坏**：保留文件和诊断，请维护者协助，不要先删整个数据目录“重置”。

报告完成和失败通知默认关闭。在「设置 → 通用」明确开启后才申请系统通知权限。
提醒只针对新完成的有效报告或失败研究，不对空结果、取消或单独投递发提醒；
点击可阅读报告或查看诊断。通知失败不改变研究结果。

## 8. 本地数据、缓存与当前边界

当前默认开发版的数据在 `~/Library/Application Support/ResearchRadar-Dev/`：

- `config/app-config.json`：App 设置、主题和收发配置，不含 secret 值。
- `state/`：队列、报告索引、计划和界面状态。
- `workspace/runs/`：报告、图片和研究 artifacts。
- `workspace/cache/model_calls/`：可重建的模型缓存。
- `jobs/`：任务记录和诊断。

不要把这个目录当成可随便清空的缓存，也不要与 CLI 的 `--root` 混用。
旧 CLI 的来源历史可通过设置中的导入入口按提示复制；不会自动导入旧报告、设置、缓存或密钥。

在「设置 → 存储空间」查看用量、设置可选模型缓存上限或确认清理缓存。
上限默认关闭，不会默认自动淘汰。当前自动容量检查在写入新缓存后进行；
降低上限后，如果任务一直命中旧缓存，占用可能持续超过新上限。
手动清理只处理 App 模型缓存，不删除报告和来源历史。
报告与普通 artifacts 是本地明文，需自行用系统磁盘加密和账户权限保护，不能当成加密文档库。

当前 App 没有 Archive/RSS 或知乎导出的操作页面；这两个现有渠道继续使用
[CLI 使用说明](usage.md)，不代表 App 已经内置这些按钮。真正的周报聚合不在本版范围内。
本地测试 DMG 不等于正式 release；安装、公开分发、公证和全部最终验收尚未完成。

若要卸载，先退出，再把选中的 `.app` 移入废纸篓。默认保留报告、App 数据和钥匙串项目；
要清理它们时，先备份并逐项确认，不要按不明路径批量删除。
