# ResearchRadar 0.3.0b1: Local Beta Draft

**Status: release notes only. Not tagged, published, or packaged as 0.3.0b1.**

## Two Ways To Use ResearchRadar

- **CLI:** Python package version `0.3.0b1`, installed from source with the existing
  [CLI instructions](../usage.md). This change does not build or publish a wheel or source archive.
- **macOS App:** a separate `.app` / DMG distribution for macOS 26 on Apple Silicon. It includes
  the Python engine; users do not need to install the CLI, Python, Homebrew, or `uv` to run it.
  Codex remains an external installation and sign-in when chosen as verifier.

Both entry points share application services, evidence rules, and renderers. They do not share
configuration automatically. CLI-only Archive/RSS and Zhihu exports remain available through CLI.
See the [English App guide](../macos-app.md) or [中文入门](../macos-app.zh-CN.md).

## Previously Verified Scope

- Native menu-bar interaction, English/Chinese setup, persisted topics, queue and scheduling.
- Chinese report reading with images; bounded keyboard and reader lifecycle/resource checks.
- Separately authorized real private email, WeChat draft creation, and cover upload.
- Notification permission/click navigation and redacted diagnostic copying.
- Real npm Codex verification of two cached readings, producing a Chinese report with
  85 publishable claims. This was not a complete fresh first-use run.
- Existing local image package/signature checks and isolated startup, reading, and exit.

These are scoped prior acceptance records, not new live tests for this version change.
See the [roadmap](../todo.md) for evidence and outstanding checks.

## Known Limits And Remaining Checks

- A complete new-user discovery-to-report run remains unverified; cached-reading acceptance
  must not be presented as fresh end-to-end acceptance.
- The installer is locally signed, not notarized or approved for public distribution.
  Direct Finder and downloaded/quarantined Gatekeeper acceptance remain unverified.
- VoiceOver, multi-display and remaining accessibility-display checks are deferred, not passed.
- Keychain may request authorization for different items/programs or after updates;
  local signing has not demonstrated stable cross-update authorization.
- Current App copies use the development workspace, not separate user profiles. Do not run
  copies concurrently against it. App scheduling stops on Quit.
- Delivery is off by default. Enabling it allows automatic delivery jobs after eligible research:
  WeChat creates drafts only, but email sends to the configured recipient. Unknown results
  are not automatically resent. No public publishing, mass-send, or subscriptions are provided.

Do not disable Gatekeeper, remove quarantine, or save plaintext credentials to bypass limitations.
No research, model call, upload, email or WeChat delivery is part of this metadata/documentation update.
