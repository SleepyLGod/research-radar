SuperLocalMemory V3.3: The Living Brain -- Biologically-Inspired Forgetting, Cognitive Quantization, and Multi-Channel Retrieval for Zero-LLM Agent Memory Systems

Research paper · new source · 2026-04-06T08:27:26Z · v1

SuperLocalMemory V3.3 implements biologically-inspired forgetting and multi-channel retrieval for local-first agent memory without cloud LLMs.

Essence

SuperLocalMemory V3.3 equips local AI coding agents with human‑like memory through mathematical forgetting, compression via precision quantization, and seven‑way cognitive retrieval, all automated by a single npm install.

Problem and Motivation

Agent memory systems treat memory as static text without dynamic cognitive processes. They lack mathematical forgetting, adaptive compression (quantization), memory consolidation into behavioral parameters, and require manual user invocation for lifecycle operations, leading to poor adoption.

Without human-like forgetting and compression, memory stores grow unbounded, retrieval becomes noisy, and privacy-sensitive environments cannot use cloud-dependent systems. A local-first, autonomic memory system can improve developer productivity and trust.

Solution Mechanism

SuperLocalMemory V3.3 implements five novel contributions: FRQAD metric for quantization-aware retrieval, Ebbinghaus adaptive forgetting with lifecycle-aware quantization, 7-channel cognitive retrieval, memory parameterization into soft prompts, and a zero-friction npm-install pipeline that automates the full memory lifecycle.

FRQAD measures distance on a Gaussian statistical manifold to prefer full-precision over quantized embeddings. Forgetting follows an exponential retention curve influenced by access frequency, importance, confirmations, and emotional salience; as memory fades, embedding precision decays across Active→Warm→Cold→Archive tiers. Retrieval fuses seven parallel channels (semantic, BM25, entity graph, temporal, spreading activation, consolidation, Hopfield) via weighted Reciprocal Rank Fusion with cross-channel intersection for multi-hop queries and ONNX reranking. Consolidated patterns become soft prompts injected at session start without retrieval.

Experiments

Six benchmarks: (1) Quantization precision: mixed-precision recall@10 drops from 1.000 (float32) to 0.680, 4-bit cosine fidelity 0.994, 2-bit 0.801. (2) Memory footprint: main process 63.3 MB, embedding worker 1058.9 MB; engine init 1.75 s. (3) Forgetting quality: simulated 30-day test with 170 facts, hot group S=11.28 (4-bit), cold S=1.69 (deleted), 6.7× discriminative power. (4) Session continuity: 10/10 facts survive restart, rank‑1 recall. (5) LoCoMo Mode A: 2 of 10 conversations (304 QA pairs), judged by Azure GPT‑5.4‑mini, best‑of‑5 rounds 70.4% overall; improvements on multi‑hop (+23.8pp) and adversarial (+12.7pp) over V3.2 baseline, but single‑hop regression (−14.9pp vs V3.2). (6) Comparison with other systems: SLM V3.3 Mode A 70.4% zero‑cloud, second only to V3.2 among zero‑cloud systems.

Related Work

SLM V3.3 introduces the first local agent memory system with mathematical forgetting and progressive quantization, the FRQAD metric on a quantized Gaussian manifold (zero prior art claimed), Hopfield associative memory as a retrieval channel, memory parameterization into soft prompts without gradient access, and a fully automated zero-friction pipeline.

Moderate. The system integrates known components (RF, ONNX reranking, Hopfield networks, spreading activation) within a new architecture. The FRQAD metric and the explicit coupling of forgetting with quantization are claimed as zero prior art, but the extent of novelty beyond a combination of existing techniques requires independent verification.

Plain-language Example

Imagine a developer who installs `npm install -g superlocalmemory`. Without any extra commands, the tool silently watches their coding sessions. Over weeks, it remembers frequently used commands and past fixes vividly (like knowing by heart where that tricky bug was documented). Less important memories slowly fade and get compressed into rougher notes. When the developer asks 'What did I do last Tuesday?', the system checks seven different mental pathways—word matches, meaning, timeline, and connections—to piece together the answer, all without ever sending data to the cloud.
